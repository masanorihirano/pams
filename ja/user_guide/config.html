JSON設定¶

PAMSのシミュレーションは1つのJSONファイルで記述します。このファイルでは、どの市場が存在するか、どのエージェントがそれらの市場で取引するか、シミュレーションをどのようにセッションに分割するか、どのイベント（ショック、サーキットブレーカーなど）が発生するかを定めます。市場の構成、エージェント集団、シナリオを変更する場合でも、通常Pythonコードはまったく必要ありません：設定ファイルを編集するだけです。

このページでは、ファイルの構成を説明し、組み込みクラスが解釈するすべてのキーを記載します。

クイックスタート¶

以下の設定ファイルのいずれかを config.json として保存し、ランナーで実行してください：

import random

from pams.logs import MarketStepPrintLogger
from pams.runners import SequentialRunner

with open("config.json", encoding="utf-8") as fp:
    runner = SequentialRunner(
        settings=fp,  # a dict or a file path also works
        prng=random.Random(42),  # fix the seed for reproducible results
        logger=MarketStepPrintLogger(),  # prints the market price at every step
    )
runner.main()

1つの市場と100体の FCNAgent エージェントからなる構成です。最初のセッションでは板の構築のみを行い（約定なし）、2番目のセッションで取引します。デフォルトのセッション設定では、各ステップで注文を出すのはランダムに選ばれた1体のエージェントのみです（セッション の maxNormalOrders を参照）。これは samples/CI2002 にあるChiarella and Iori (2002) の設定に従ったもので、そちらではさらに meanReversionTime も設定しています。

ファイル構造¶

ファイルのルートはJSONオブジェクトで、2種類のエントリを持ちます：

  • 何をどの順序で生成するかを列挙する simulation ブロック、および

  • 名前付きブロック：それ以外のすべてのトップレベルのキーです。キーは任意に付けた名前で、ブロックには市場グループ、エージェントグループ、またはイベントの設定を記述します。

名前付きブロックは、それ自体では何もしません。その名前が参照されたときにのみ使われます：

ブロック名を記載する場所

結果

simulation.markets

ブロックは 市場グループ （1つ以上の市場）になります。

simulation.agents

ブロックは エージェントグループ （1つ以上のエージェント）になります。

セッションの events

ブロックはそのセッションに紐づく イベント になります。

他のブロック内の "extends"

他のブロックがこのブロックのキーを継承します（extends による継承 を参照）。extends を通じてのみ使われるブロックはテンプレートです。

ブロック名とクラスは互いに独立しています：クラスは "class" で選択され、名前は単なるラベルです。"FCNAgents": {"class": "FCNAgent", ...} と "Noise traders": {"class": "FCNAgent", ...} はどちらも同じように有効です。

グループ名とインスタンス名¶

市場グループは複数の市場を作成できます（"numMarkets": 2）。このとき、グループは グループ名 （ブロック名、例えば SpotMarkets）を持ち、各市場は インスタンス名 （例えば SpotMarkets-0 と SpotMarkets-1、インスタンス名 を参照）を持ちます。キーによって、指定する名前の種類が異なります：

キー

指定する名前

simulation.markets, simulation.agents, sessions[].events, extends

ブロック名

エージェントグループの markets

市場の グループ名 （グループ内のすべての市場が取引可能になります）

IndexMarket の markets、fundamentalCorrelations.pairwise、MarketMakerAgent の targetMarket、イベントの target と targetMarkets

市場の インスタンス名

グループが市場を1つだけ作成し、prefix も from / to も使わない場合は両者の名前が一致するため、この区別が主に重要になるのは複数の市場を持つグループです。これらのキーを使う場合は、市場が1つでも名前が異なります： "prefix": "Stock" とするとインスタンス名は Stock になります。

このページで使う表記¶

required

このキーは省略できません。省略すると、シミュレーションのセットアップ時にエラーになります。

optional

このキーは省略できます。省略した場合はデフォルト値が使われます。

conditional

特定の状況でのみ必須です。その条件は各キーの説明に記載しています。

JsonRandom

値に確率分布を指定でき、その場合はエージェントごとに個別に値が抽出されます（ランダムパラメータ（JsonRandom） を参照）。このバッジのないキーには通常の値を指定します。

deprecated

古いキーです。キーによって、警告付きで引き続き動作する、警告付きで無視される、エラーになる、のいずれかです（各キーの説明を参照）。新しい設定ファイルでは使わないでください。

重要

  • 設定ファイルは 厳密なJSON でなければなりません：コメントや末尾のカンマは使えません。True / False ではなく true / false を使ってください。メモを残すには、"MEMO" のようにPAMSが読み込まないキーを追加します（サンプルでもこの方法を使っています）。

  • 未知のキーは警告なしに無視されます。 "numMarkets" を "numMarket" と書くようなタイプミスはエラーにならず、代わりにデフォルト値が使われます。綴りと大文字・小文字を注意深く確認してください。

  • 一部のキーでは、JSONの数値の型がチェックされます。triggerChangeRate （PriceLimitRule、TradingHaltRule）と OrderMistakeShock の priceChangeRate は浮動小数点数で書く必要があります（1 ではなく 1.0）。iterationSteps、outstandingShares、numParallel、triggerTime、shockTimeLength、haltingTimeLength、および ArbitrageAgent と OrderMistakeShock の orderVolume / orderTimeLength は整数で書く必要があります（100.0 ではなく 100）。

セッション¶

シミュレーションは、0から始まる1つの時計に沿って離散的な ステップ で進みます。ステップは セッション に分割され、セッションは順に1つずつ実行されます。各セッションは、エージェントが注文を出せるかどうかと、注文が約定するかどうかを決めます。典型的な設定では、板を埋めるだけのウォームアップセッションの後に、メインの取引セッションが続きます：

"sessions": [
  {"sessionName": "warmup", "iterationSteps": 100,
   "withOrderPlacement": true, "withOrderExecution": false, "withPrint": true},
  {"sessionName": "main", "iterationSteps": 500,
   "withOrderPlacement": true, "withOrderExecution": true, "withPrint": true}
]

ここでは、warmup がステップ0から99まで、main がステップ100から599までを占めます。一般に、セッションはそれより前のすべてのセッションの iterationSteps の合計のステップから始まります。

キー

値

説明

sessionName required

文字列

セッションの名前です。どのJSON値も文字列に変換され、変換後の名前は一意でなければなりません（0 と "0" は衝突します）。組み込みのロガーは、この名前ではなくリスト内でのセッションの位置（0、1、...）を表示します。

iterationSteps required

整数

セッションのステップ数です。JSONの整数で指定する必要があります（100.0 は不可）。

withOrderPlacement required

真偽値

false の場合、セッション中はどのエージェントにも注文を求めません。それでも時刻は進み、ファンダメンタル価格は変動し、板上の注文が有効期限切れになることもあります。

withOrderExecution required

真偽値

false の場合、注文は板に入りますが約定せず、市場価格は直前の値のまま変わりません。板に残っている（有効期限切れでない）注文は、後のセッションで約定が許可されると約定する可能性があります。

withPrint required

真偽値

必須ですが、現在PAMSでは使われていません（plhamの設定ファイルとの互換性のために残されています）。何が出力されるかは、ランナーに渡したロガーによって決まります。

maxNormalOrders optional

0以上の整数

1ステップで注文を出す通常エージェント（高頻度エージェント以外）の最大数です。デフォルトは 1 です。数えるのは注文ではなく エージェント です。1つのエージェントが一度に複数の注文を出すこともあります。

maxHighFrequencyOrders optional

0以上の整数

セッションのキーはいずれも JsonRandom 記法を受け付けません。また、セッションオブジェクトは extends に対応していません（他の未知のキーと同様に無視されます）。

1ステップで行われる処理

セッションの各ステップでは、次の処理が行われます：

  1. ステップの前にフックされたイベントが実行されます（FundamentalPriceShock など）。

  2. withOrderPlacement が true の場合、通常エージェントをシャッフルし、1つずつ順に注文を求めます（各エージェントにはすべての市場が渡されます）。注文を1つ以上返したエージェントの数が maxNormalOrders に達するか、すべてのエージェントに問い合わせた時点で、問い合わせを終了します。注文を返さなかったエージェントは数に含めません。

  3. 集めた注文リストはランダムな順序で処理されます。各注文（またはキャンセル）は対象の市場に送られ、withOrderExecution が true で、かつその市場が TradingHaltRule によって売買停止されていなければ、市場は直ちに注文を約定させます（連続ダブルオークション）。

  4. 各通常エージェントの注文の後、確率 highFrequencySubmitRate で 高頻度ラウンド が行われます。このラウンドでは、高頻度エージェントをシャッフルし、注文を返したエージェントの数が maxHighFrequencyOrders に達するまで問い合わせます。各エージェントの注文は、次のエージェントに問い合わせる前にすぐ処理（および約定）されるため、高頻度エージェントは直前に出された注文に反応します。

  5. ステップ終了時のログが書き出され（MarketStepPrintLogger が出力するのはこれです）、その後、ステップの後にフックされたイベントが実行されます。

  6. 時刻が1ステップ進みます。有効期限切れの注文は板から取り除かれ、ファンダメンタル価格が変動します。

重要

  • デフォルトの maxNormalOrders: 1 では、設定ファイルで作成するエージェントの数にかかわらず、1ステップに注文を出す通常エージェントは 1つ だけです。同じステップでより多くのエージェントを行動させるには、この値を大きくしてください。その場合、すべてのエージェントが同じ市場状態に基づいて判断します。つまり、どのエージェントも、同じステップで他のエージェントが出した注文を見ることはできません。

  • 高頻度エージェント（ArbitrageAgent と MarketMakerAgent）は、各通常エージェントの注文の後に行われ得る高頻度ラウンド（上記の手順4）で のみ 行動します。通常エージェントが1つも注文を出さなかったステップでは行動せず、highFrequencySubmitRate: 0.0 とすると無効になります。

extends による継承¶

"extends": "OtherBlock" は OtherBlock のすべてのキーをこのブロックにコピーし、このブロックに書かれたキーは継承されたキーを上書きします。親ブロック自体も extends を使えるため、継承の連鎖は再帰的に解決されます。ブロックの親は1つだけです： extends はリストではなく単一のブロック名を取ります。市場グループ、エージェントグループ、イベントブロックはいずれも extends に対応しています。

"FCNBase": {
  "class": "FCNAgent", "numAgents": 100, "assetVolume": 50, "cashAmount": 10000,
  "fundamentalWeight": {"expon": [1.0]}, "chartWeight": {"expon": [0.0]},
  "noiseWeight": {"expon": [1.0]}, "noiseScale": 0.001,
  "timeWindowSize": [100, 200], "orderMargin": [0.0, 0.1]
},
"SpotFCNAgents": {"extends": "FCNBase", "markets": ["SpotMarkets"]},
"Chartists": {"extends": "FCNBase", "markets": ["SpotMarkets"], "chartWeight": {"expon": [1.0]}}

ここで FCNBase はテンプレートです： simulation.agents に列挙されていないため、このブロックから直接エージェントが作成されることはありません。両方の子ブロックは "numAgents": 100 を継承するため、それぞれ100体のエージェントを作成します（SpotFCNAgents-0 から SpotFCNAgents-99 まで、および Chartists-0 から Chartists-99 まで）。

  • マージは浅く行われます：子ブロックのオブジェクト値（例： {"expon": [1.0]}）は親の値を丸ごと置き換えます。

  • from と to が継承されることはありません。numMarkets、numAgents、prefix は市場グループとエージェントグループでは 継承されます。そのため、親が numAgents を設定しているのに子が from / to を設定すると失敗します。また、列挙されている2つのグループが同じ prefix を継承している場合（例：1つのテンプレートの2つの子、または子と列挙されているその親）、両者の from / to の範囲が重ならない限り名前が重複します。例えば、"prefix": "Trader-" を持つ（numAgents を持たない）テンプレートの2つの子が "from": 0, "to": 49 と "from": 50, "to": 99 を使うと、合わせて Trader-0 から Trader-99 までが作成されます。それ以外の場合は、各グループに固有の prefix を指定してください。

  • イベントブロックは numMarkets、from、to、prefix を継承しません。

  • 存在しない親の指定と、ループ（A が B を継承し、それがさらに A を継承する）はエラーになります。

ファンダメンタル価格の動き方

各市場のファンダメンタル価格 \(P^f_t\) は、シミュレーションの1ステップごとに1歩進む幾何ランダムウォークに従います：

\[\ln P^f_{t+1} - \ln P^f_t = \mu + \sigma \varepsilon_t, \qquad \varepsilon_t \sim \mathcal{N}(0, 1)\]

ここで \(\mu\) は fundamentalDrift、\(\sigma\) は fundamentalVolatility です。どちらも1ステップあたりの値であり、年率換算ではありません。異なる市場のショック \(\varepsilon_t\) は、fundamentalCorrelations で相関を持たせない限り独立です。ファンダメンタル価格は、注文の約定を行わないセッションも含め、すべてのセッションで変動し続けます。

市場価格の決まり方

ステップ0の開始時には、エージェントは初期の市場価格を参照します。それ以降、セッションが注文を約定させている間は、市場価格は直近の約定価格、まだ何も約定していなければ仲値になります。注文が約定しない間（withOrderExecution: false の場合や売買停止中）は、市場価格は直前の値のまま変わりません。

新たに到着した注文は、板上でマッチングした注文（先に出されていた注文）の価格で約定します。成行注文は、マッチングした指値注文の価格で約定します。1つの注文が一度に複数の価格水準にまたがって約定する場合、それらの約定はすべて、そのうち最後の（最も不利な）価格で行われます。

simulation.fundamentalCorrelations は、市場のペアについて、ファンダメンタル価格のランダムなショックに相関を持たせます：

FCNエージェントが注文を決める仕組み

ステップ \(t\) において、エージェントは、市場価格が \(P_t\)、ファンダメンタル価格が \(P^f_t\) である取引可能な各市場について、次の期待対数リターンを計算します。

\[\hat{r} = \frac{1}{w_F + w_C + w_N} \left( w_F \frac{1}{\tau_r} \ln\frac{P^f_t}{P_t} + w_C \frac{1}{\tau'} \ln\frac{P_t}{P_{t-\tau'}} + w_N \sigma_N \varepsilon \right), \qquad \varepsilon \sim \mathcal{N}(0, 1),\]

ここで \(\tau' = \min(t, \tau)\) であり（2つの分母では、1未満の \(\tau_r\) および \(\tau'\) の値は1に置き換えられます）、期待価格は \(\hat{P} = P_t \exp(\hat{r} \tau)\) です。エージェントは \(\hat{P} > P_t\) ならば買いの指値注文を出し、また \(\hat{P} < P_t\) ならば売りの指値注文を出します。いずれも数量1、有効期間 \(\tau\) の注文です：

  • "fixed"：買いは \(\hat{P}(1 - k)\)、売りは \(\hat{P}(1 + k)\) の価格で注文します。

  • "normal"：価格 \(\hat{P} + k \varepsilon'\) で注文します（\(\varepsilon' \sim \mathcal{N}(0, 1)\)）。

チャーティスト成分は常にトレンドに追随します。逆張りの挙動を指定するキーはありません。

警告

FCNのパラメータの範囲は、シミュレーションのセットアップ時ではなく、エージェントが最初に注文を出すときに初めてチェックされます。そのため、重みに対する {"normal": [...]} のように不正な値を生成しうる分布を指定すると、シミュレーションが途中で AssertionError により停止することがあります（3つの重みがすべて0の場合は ZeroDivisionError）。また timeWindowSize に0へ切り捨てられる値（0.5 や、0から始まる範囲など）を指定すると、エージェントは警告なしに注文を一切出さなくなり、負の値を指定するとシミュレーションが AssertionError で停止します。

MarketShareFCNAgent¶

"class": "MarketShareFCNAgent" （pams.agents.MarketShareFCNAgent）は FCNAgent とまったく同じキーを持ちます。取引可能なすべての市場に注文を出す代わりに、意思決定のたびに 1つ の市場を選びます。各市場が選ばれる確率は、現在のステップとその前の timeWindowSize ステップにその市場で約定した数量に比例します。取引可能な市場が少なくとも1つ必要です。

時間窓内にいずれかの市場で約定がある間は、約定のない市場が選ばれる確率はほぼ0になります（重みは約定数量に 1e-10 を加えた値です）。そのため、ある市場で取引が始まると、エージェントは通常その市場を選び続け、他の市場の出来高は0のままになります。どの市場にも約定がない場合は、すべての市場が等確率で選ばれます。開始時の配分については samples/market_share が、初期の出来高（tradeVolume）を設定するユーザー定義の市場クラスを用いて制御しています。

ArbitrageAgent¶

"class": "ArbitrageAgent" （pams.agents.ArbitrageAgent）は、取引可能なすべての IndexMarket を監視する高頻度エージェントです。インデックス市場の市場価格がインデックス値（構成市場の市場価格の加重平均。詳しくは IndexMarket を参照）を下回り、その差が orderThresholdPrice を超えると、インデックスを買い、各構成市場で売ります（いずれも各市場の現在の市場価格での指値注文）。逆の場合はその反対の売買を行います。このエージェント固有のキーはいずれも JsonRandom 記法に対応していません（cashAmount と assetVolume は対応しています）。

MarketMakerAgent¶

"class": "MarketMakerAgent" は、発注を求められるたびに targetMarket に買いと売りの指値注文（数量1）を1つずつ出す高頻度エージェントです。注文は、取引可能な すべての 市場の最良価格を中心に配置されます（下記参照）。古い注文は取り消されず、発注から orderTimeLength ステップ後に失効します。

TestAgent¶

"class": "TestAgent" はランダムな注文を出すエージェントで、markets、cashAmount、assetVolume 以外に固有のキーはありません。PAMS自体をテストするためのものであり、研究には使用しないでください。

イベント¶

イベントは、価格にショックを与える、注文価格を制限する、売買を停止する、誤った注文を投入するといった形でシミュレーションの流れを変えます。イベントは名前付きブロックで定義し、その "class" （必須）でイベントクラスを指定します。セッションの events にブロック名を記載すると、そのセッションにイベントが割り当てられます：

"sessions": [
  {"sessionName": "warmup", "iterationSteps": 100, "...": "..."},
  {"sessionName": "main", "iterationSteps": 500, "...": "...", "events": ["PriceDrop"]}
],
"PriceDrop": {
  "class": "FundamentalPriceShock",
  "target": "Market",
  "triggerTime": 100,
  "priceChangeRate": -0.1
}

タイミングの規則：

  • triggerTime は イベントを記載したセッションの開始時点から 数えたステップ数です。上の例では main がステップ100から始まるため、ショックはステップ200で発生します。triggerTime がセッションの終了を超える場合、イベントは後のセッションで発動し、その時点でシミュレーションがすでに終了していれば発動しません。

  • トリガー時刻を持たないルール（PriceLimitRule と TradingHaltRule）は、どのセッションに記載されていても、ステップ0から シミュレーション全体 にわたって有効です。

  • 同じブロックを2つのセッションに記載すると、独立した2つのイベントが作成されます。PriceLimitRule や TradingHaltRule は 1つの セッションにのみ記載してください：1つだけですでにすべてのセッションに適用されるうえ、2つ目の TradingHaltRule は同じ市場を二重に監視することになり（それぞれが独自の売買停止回数を持ちます）、これはサポートされていません。

どのイベントも "enabled": false を受け付け、これによりイベントを削除せずに無効化できます（デフォルトは true）。対照実験にはこれを使ってください：同じシードを使えば、イベントを無効化した実行は、イベントが作用するステップまではイベントありの実行と一致します。一方でイベントを events から削除すると、最初から乱数が変わってしまいます。

率はすべて比率で指定します（0.05 は5%を意味します）。イベントのキーはいずれもJsonRandom記法を受け付けません。

FundamentalPriceShock¶

1つの市場のファンダメンタル価格を \(1 + r\) 倍します（pams.events.FundamentalPriceShock）。この変化は恒久的で、ファンダメンタル価格は新しい水準からランダムウォークを続けます。ショック以降は すべての 市場のファンダメンタル価格が新たに生成された乱数で推移するため、同じシードでも、ショックありの実行となしの実行とでは、それ以降のファンダメンタル価格のノイズは一致しません（ドリフトとボラティリティは変わりません）。

PriceLimitRule¶

指値注文の価格を、初期価格を中心とする価格帯の中に制限します（pams.events.PriceLimitRule）。価格が \([P_0 (1 - r), P_0 (1 + r)]\) の範囲外にある指値注文は、価格帯の最も近い端に移動されます。ここで \(P_0\) はステップ0における市場価格で、以後シミュレーション終了まで固定されます。最初のセッションが withOrderExecution: false の場合（本ページの例と同様）、\(P_0\) は市場の marketPrice になります。そうでない場合は、ステップ0の間の取引によって変化することがあります。成行注文は影響を受けません。

TradingHaltRule¶

サーキットブレーカーです（pams.events.TradingHaltRule）。対象市場のいずれかで約定が発生した後、市場価格がステップ0における価格 \(P_0\) （PriceLimitRule と同じ定義）から \(P_0 \times r \times (n + 1)\) 以上乖離していた場合、すべての 対象市場が売買停止になります（\(n\) はそれまでの売買停止の回数）。売買停止中も注文は受け付けられますが、約定は一切行われません。売買は、売買停止の開始から haltingTimeLength + 1 ステップ後に再開されます。

ランダムパラメータ（JsonRandom）¶

エージェントのパラメータのうち JsonRandom が付いたものには、固定の数値または分布を指定できます。1つのグループが多数のエージェントを生成する場合、各エージェントが自分の値を1回だけサンプリングします （assetVolume は取引可能な市場ごとに1回）。サンプリングはシミュレーションのセットアップ時に行われ、シミュレーション中に値が変わることはありません。これにより、1つのブロックで異質なエージェントの集団を記述できます。

表記

値

300 または {"const": [300]}

常に300です。

[a, b] または {"uniform": [a, b]}

\(a \le x < b\) の一様分布です。

{"normal": [mu, sigma]}

平均 mu、標準偏差 sigma の正規分布です。負の値になることもあります。

{"expon": [lam]}

平均 が lam の指数分布です（lam はスケールであり、レートではありません）。{"expon": [0.0]} は常に0です。

  "class": "FCNAgent",
  "numAgents": 100,
  "markets": ["Market"],
  "cashAmount": {"uniform": [5000, 15000]},
  "assetVolume": [40, 61],
  "fundamentalWeight": {"expon": [1.0]},
  "chartWeight": {"expon": [0.0]},

整数のパラメータ（assetVolume、timeWindowSize、meanReversionTime、および MarketMakerAgent の orderTimeLength）は、四捨五入ではなく 切り捨て になります。したがって [100, 200] では100から199までの整数になります。200を含めるには [100, 201] と書いてください。

JsonRandom が使えるのは、このページで JsonRandom が付いているエージェントのキーだけです。それ以外のキーには通常の値しか指定できません。すなわち、市場、セッション、イベント、および simulation のキーと、バッジのないエージェントのキー（marginType、targetMarket、および ArbitrageAgent のキーである orderVolume、orderThresholdPrice、orderTimeLength など）です。これらのキーに分布を指定すると失敗します。場合によっては、シミュレーションの実行中になって初めて失敗します。

ユーザー定義クラス¶

独自の市場、エージェント、イベントも組み込みのものと同じように設定します。各クラスを main() の呼び出し前にランナーに登録し、クラス名で参照してください：

from pams.agents import FCNAgent
from pams.runners import SequentialRunner


class MyAgent(FCNAgent):
    def setup(self, settings, accessible_markets_ids, *args, **kwargs):
        super().setup(settings, accessible_markets_ids, *args, **kwargs)
        # read your own keys from the block
        self.my_parameter = settings.get("myParameter", 1.0)


runner = SequentialRunner(settings="config.json")
runner.class_register(cls=MyAgent)
runner.main()

"MyAgents": {"extends": "FCNAgents", "class": "MyAgent", "myParameter": 2.0}

設定が Python の dict の場合は、名前の代わりにクラスそのものを class の値に指定することもできます。このクラスはそのまま使われるため、class_register は不要で、名前が一意である必要もありません：

config = {
    # ... the other blocks
    "MyAgents": {"extends": "FCNAgents", "class": MyAgent, "myParameter": 2.0},
}
runner = SequentialRunner(settings=config)
runner.main()

JSON ファイルはクラスを保持できないため、これは Python の dict でのみ使えます。ブロックに指定したクラスは、他の値と同じように extends で継承されます。

  • ブロック（extends を解決した後の内容から numAgents / numMarkets、from、to および prefix を除いたもの）は setup(settings=...) に渡されるため、追加した任意のキーをそこで利用できます。JsonRandom 記法を受け付けるには setup 内で JsonRandom(prng=self.prng).random(settings["myParameter"]) により値を生成してください（インポートは from pams.utils import JsonRandom、詳細は JsonRandom を参照）。戻り値は常に float なので、整数パラメータには自分で int() を適用してください。

  • 文字列で指定するクラス名は一意でなければなりません：組み込みクラスと同じ名前のクラス（例：独自の FCNAgent）は曖昧となりエラーになります。各クラスは一度だけ登録してください。

  • エージェントクラスは Agent を、市場クラスは Market を、イベントクラスは EventABC を継承する必要があります。エージェントが HighFrequencyAgent を継承している場合、高頻度エージェントとしてスケジュールされます。

  • samples/user_class と samples/market_share に完全な例があります。

並列ランナー¶

MultiThreadAgentParallelRunner と MultiProcessAgentParallelRunner （いずれも実験的機能）は同じ設定ファイルを読み込み、同じシードであれば SequentialRunner と同じ結果になります。これらは通常エージェントの submit_orders を並列に呼び出し、それ以外はすべて逐次的に処理します。

  • 速度：Python の GIL のため、スレッドランナーが効果を持つのは submit_orders が I/O を待つ場合（例えば外部モデルの呼び出し）のみで、組み込みエージェントは高速化されません。プロセスランナーは、ステップごとにシミュレーション全体がワーカープロセスにコピーされるため（後述）、はるかに低速です。あわせて プラットフォーム も参照してください。

  • ユーザー定義エージェント は submit_orders 内で共有オブジェクト（市場、他のエージェント、ロガー）を変更してはいけません。プロセスランナーでは、エージェントが submit_orders 内で自身の属性に加えた変更は失われます。このような状態は、メインプロセスで実行される executed_order などのコールバックで更新してください。

ワーカースレッドまたはワーカープロセスの数は simulation.numParallel で設定します（simulation ブロック を参照。デフォルト：CPU数から1を引いた値、ただし1以上）。

同時に注文の提出を求められるエージェントは最大 maxNormalOrders 個なので、セッションの maxNormalOrders を超える分のワーカーは待機したままになります。すべてのセッションで numParallel が maxNormalOrders より大きい場合（例えばデフォルト設定の場合）は警告が表示されます。また maxNormalOrders はモデルの一部であり、値を大きくするとシミュレーション結果が変わります。まずモデルに合わせてこの値を決め、その後 numParallel をその値以下に設定してください。

プロセスランナーを使う場合は、ランナーを作成して実行するコードを if __name__ == "__main__": の下に置いてください（Windows と macOS、およびワーカープロセスが fork で起動されなくなった Python 3.14 以降の Linux では必須です。これがないと実行が失敗するかハングします）。また、ワーカープロセスがインポートできるよう、ユーザー定義クラスはノートブックや対話型セッションではなく .py ファイル内で定義してください。

simulation.startMethod は、プロセスランナーがワーカープロセスを起動する開始方式を設定します："spawn" （Windows と macOS でのデフォルト）、"fork" （Python 3.13 までの Linux でのデフォルト）、"forkserver" （Python 3.14 以降の Linux でのデフォルト）のいずれかです。そのプラットフォームで multiprocessing.get_all_start_methods() が返す値のみ指定でき、それ以外の値はエラーになります。このキーがない場合は、ランナーのサブクラスが別のデフォルトを設定していない限り、プラットフォームのデフォルトが使われます。fork されたプロセスでは動作しないライブラリ（CUDA を使う PyTorch、TensorFlow、JAX など）をエージェントが使う場合は "spawn" を使ってください。開始方式によってシミュレーション結果は変わりません。

プロセスランナーはタスクごとに、エージェントと市場を、それらが参照するすべてのもの（シミュレータ、他のエージェント、イベント、ロガー）とともに pickle 化します。そのため、ユーザー定義のエージェント、市場、イベント、ロガーは pickle 可能でなければなりません。例えば、ファイルを開いたまま保持するロガーは TypeError: cannot pickle '_io.TextIOWrapper' object で失敗します。このようなデータはメモリ上に保持し、実行後にファイルへ書き出してください。

このような参照があるため、各タスクではシミュレーション全体がコピーされます。コピーの大きさはエージェント 1 個あたり約 4 KB（1000 個のエージェントで約 4 MB）で、その大部分は各エージェントの乱数生成器の状態です。コピーには数十ミリ秒かかり、組み込みエージェントの submit_orders よりはるかに長い時間がかかります。このコストを抑えるため、同時に注文の提出を求められるエージェントは最大 numParallel 個のタスクに分けられます。ニューラルネットワークのモデルなど、エージェントが保持するオブジェクトは、他のエージェントのタスクも含めてすべてのタスクでコピーされます。このようなオブジェクトは pickle 化の対象から除外し（例えば __getstate__ を使います）、読み取り専用であれば、代わりにワーカープロセスごとに 1 回だけ読み込んでください（プラットフォーム を参照）。

JAX/Flax ランナー¶

JaxAgentParallelRunner （実験的）は、submit_orders で JAX を使うエージェント（例えば Flax のモデル）のためのプロセスランナーです。JAX は PAMS と一緒にはインストールされないため、pip が PAMS で動作するバージョンを選ぶように、PAMS と同じコマンドで各自インストールしてください（例えば pip install pams jax flax）。このランナーは、simulation.startMethod が設定されていない限り、"spawn" でワーカープロセスを起動します。各ワーカープロセスは、タスクを実行する前に一度だけ、simulation の以下のキーで JAX を設定します。これらのキーは他のランナーでは無視されます：

キー

値

説明

jaxPlatforms optional

文字列

ワーカープロセスで JAX が使うプラットフォームです。例えば "cpu" や "cuda" です（JAX の jax_platforms）。デフォルト：環境変数 JAX_PLATFORMS が設定されていればその値、設定されていなければ JAX が選択します。

jaxPreallocate optional

真偽値

各ワーカープロセスで JAX が GPU メモリを事前確保するかどうかです（XLA_PYTHON_CLIENT_PREALLOCATE）。デフォルト：環境変数 XLA_PYTHON_CLIENT_PREALLOCATE が設定されていればその値、設定されていなければ false。ワーカープロセスが GPU を共有できるようにするためです（JAX はデフォルトで GPU メモリの 75% を事前確保します）。

jaxMemoryFraction optional

(0, 1] の数値

各ワーカープロセスで JAX が使える GPU メモリの割合です（XLA_PYTHON_CLIENT_MEM_FRACTION）。デフォルト：環境変数 XLA_PYTHON_CLIENT_MEM_FRACTION （または XLA_CLIENT_MEM_FRACTION）が設定されていればその値、設定されていなければ JAX のデフォルト（0.75）。

これらのキーはメインプロセスの JAX を設定しません。このランナー向けのエージェントの書き方は プラットフォーム を参照してください。

トラブルシューティング¶

エラーにならない落とし穴¶

以下の誤りはエラーにはなりませんが、シミュレーションの内容を変えてしまいます：

  • 綴りや配置を誤ったキーは無視されます：例えば "numMarket" や "maxNormalOrder" と書くとデフォルト値が使われ、セッション内ではなく simulation 内に書いた events からはイベントが作成されません。

  • デフォルト（maxNormalOrders: 1）では 1ステップに注文を出す通常エージェントは1つだけです。

  • あるステップで注文を出す通常エージェントがいない場合、または highFrequencySubmitRate が 0.0 の場合には 高頻度エージェントは一切行動しません。

  • withPrint は 効果がありません。代わりに MarketStepPrintLogger などのロガーを使用してください。

  • イベントルールはすべてのセッションで有効です：2番目のセッションにのみ記載した PriceLimitRule や TradingHaltRule は、1番目のセッションの間にも適用されます。

  • triggerTime は イベントを記載したセッションの開始時点から数えます。ステップ0からではありません。セッションの終了より後の時刻を指定すると、イベントは後続のセッションで発火するか、まったく発火しません。

  • [a, b] は b を 決して生成せず、整数パラメータは切り捨てられます。

  • エントリの追加、削除、並べ替えは乱数を変えてしまいます。 ランナーはすべての市場、エージェント、セッション、イベントのエントリについてリスト順にシードを生成するため、このような編集を行うと、同じシードでも通常は実行全体が変わります。比較実行のためにイベントを無効にするには、リストに記載したまま "enabled": false を指定してください。

よくあるエラー¶

エラー

原因と対処

JSONDecodeError: Expecting ...

ファイルが厳密なJSONではありません：末尾のカンマ、コメント、シングルクォート、あるいは true / false / null の代わりに書かれた True / False / None が含まれています。エラーメッセージに行番号と列番号が示されます。

class for X is found 0 times

未知のクラス名、または runner.class_register で登録されていないユーザー定義クラスです。

class for X is found 2 times

同じ名前のクラスが2つある（例：組み込みクラスと同じ名前を付けた独自クラス）か、同じクラスが2回登録されています。クラス名を変更するか、1回だけ登録してください。

market class for X does not inherit Market class （エージェントクラスとイベントクラスも同様）

ブロック X の class の種類が誤っています（例：市場のブロックにエージェントクラスを指定している）。

class for X must be a class name (str) or a class, but Y is given

Python の dict による設定で、ブロック X の class の値 Y が文字列でもクラスでもありません（例：None）。

X setting is missing in config

simulation.markets または simulation.agents に挙げた名前に対応するブロックがありません。綴りを確認してください。

KeyError: 'X'

名前が見つかりません。典型的な原因は次のとおりです：

  • セッションの events に、ブロックが定義されていないエントリがある；

  • エージェントの markets に市場の インスタンス名 （Market-0）を指定している（グループ名を使ってください）；

  • FundamentalPriceShock.target、MarketMakerAgent.targetMarket、IndexMarket.markets または fundamentalCorrelations にグループ名を指定している（インスタンス名を使ってください）；

  • FCNAgent の必須パラメータが不足している。

X does not exist / market X is not exists

PriceLimitRule または TradingHaltRule の targetMarkets にある名前、あるいは OrderMistakeShock の target が、市場のインスタンス名になっていません。グループ名ではなくインスタンス名（Market-0）を使ってください。

order for an inaccessible market is not allowed

エージェントが取引できない市場に注文を出しました： targetMarket が自身の markets に含まれていない MarketMakerAgent や、markets に構成市場が含まれていない ArbitrageAgent がこれに当たります。メッセージに示された市場グループをエージェントの markets に追加してください。

cancel order for an order of another agent is not allowed

ユーザー定義のエージェントが、自身の agent_id を持ちながら、order_id、価格、注文が出されたステップ、売買の別、注文の種類が他のエージェントの出した注文と同じである注文の Cancel を出しました。エージェント自身が出した注文だけを取り消してください。

シミュレーション実行中に発生する、数値を伴う KeyError （KeyError: 0 など）

target が IndexMarket である FundamentalPriceShock です。代わりにその構成市場にショックを与えてください。

market name X is duplicate / agent name X is duplicate

2つのグループが同じインスタンス名を生成しています（例：同じグループを2回列挙している、または prefix を継承している）。

X.numAgents and (X.from or X.to) cannot be used at the same time

個数と範囲が両方指定されています（個数が extends を通じて継承されている場合もあります）。

triggerChangeRate have to be float （および同種のエラー）

数値は浮動小数点数（0.05、1.0）で、int 型のキーでは整数（100.0 ではなく 100）で記述してください。

outstandingShares is required in component market setting

IndexMarket の構成市場に outstandingShares がないか、構成市場のグループが simulation.markets でインデックス市場より後に列挙されています。

For applying fundamental correlation fo X, fundamentalVolatility for X is required

fundamentalCorrelations に含まれる市場には、0より大きい fundamentalVolatility が必要です。

hifreqSubmitRate is replaced to highFrequencySubmitRate （警告）

非推奨のキーの名前を変更してください。maxHifreqOrders についても同様です。

order price does not accord to the tick size （警告）

エージェントが tickSize の倍数でない価格を提出したため、価格が丸められました。FCNエージェントでは通常のことです。

ArbitrageAgent X can access the index market Y but not its component markets Z （警告）

市場 Z の市場グループをエージェントの markets に追加してください。追加しない場合、それらの市場への注文はシミュレーション実行中に失敗します。

ArbitrageAgent X cannot access any index market （警告）

このエージェントは注文を一切出しません。IndexMarket の市場グループとその構成市場の市場グループを、エージェントの markets に追加してください。

シミュレーション実行中の AssertionError

多くの場合、エージェントのパラメータが範囲外である（FCNAgentの警告を参照）か、PriceLimitRule の targetMarkets に含まれていない市場への注文が原因です。

設定ファイルのサンプル¶

リポジトリの samples ディレクトリには、完全な設定ファイルと、それらを実行するための main.py が含まれています。サンプルはパッケージと一緒にはインストールされないため、リポジトリをクローンし、そのルートから実行してください。例：

python -m samples.CI2002.main --config samples/CI2002/config.json --seed 1

examples ディレクトリには、これらのサンプルの大半について、設定をPythonのdictとして記述したJupyterノートブックがあります。

注釈

samples/CI2002、samples/test および samples/user_class は非推奨のセッションキー hifreqSubmitRate を、samples/market_share は maxHifreqOrders をまだ使用しているため、実行すると非推奨の警告が表示されます。ご自身の設定ファイルでは新しい名前を使ってください。
