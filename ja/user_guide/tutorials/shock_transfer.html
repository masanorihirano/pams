裁定取引による市場間のショック伝搬¶

このチュートリアルは、同じケースを扱うPlhamのチュートリアル（ShockTransferMain とその ユースケース）に沿っています。このケースは鳥居・中川・和泉（2015）に基づいています。2つの株式（spot 1とspot 2）と、それらから構成されるインデックスがあります。ステップ100で、spot 1に関する悪いニュースにより、そのファンダメンタル価格が10%下がります。spot 2には何も起こりませんが、裁定エージェントはspot 2をspot 1やインデックスと合わせて取引します。ショックは裁定エージェントを通じてspot 2に届くでしょうか。完全なスクリプトは tutorial_shock_transfer.py です。プロットには matplotlib が必要ですが、これはPAMSと一緒にはインストールされません（pip install matplotlib）。

設定¶

スクリプトでは、samples/shock_transfer の設定をPythonのdictとして使います：

CONFIG: Dict[str, Any] = {
    "simulation": {
        "markets": ["SpotMarket-1", "SpotMarket-2", "IndexMarket-I"],
        "agents": ["FCNAgents-1", "FCNAgents-2", "FCNAgents-I", "ArbitrageAgents"],
        "sessions": [
            {
                "sessionName": 0,
                "iterationSteps": 100,
                "withOrderPlacement": True,
                "withOrderExecution": False,
                "withPrint": True,
                "maxNormalOrders": 3,
                "maxHighFrequencyOrders": 0,
            },
            {
                "sessionName": 1,
                "iterationSteps": 500,
                "withOrderPlacement": True,
                "withOrderExecution": True,
                "withPrint": True,
                "maxNormalOrders": 3,
                "maxHighFrequencyOrders": 5,
                "events": ["FundamentalPriceShock"],
            },
        ],
    },
    "FundamentalPriceShock": {
        "class": "FundamentalPriceShock",
        "target": "SpotMarket-1",
        "triggerTime": 0,
        "priceChangeRate": -0.1,
        "enabled": True,
    },
    "SpotMarket": {
        "class": "Market",
        "tickSize": 0.00001,
        "marketPrice": 300.0,
        "outstandingShares": 25000,
    },
    "SpotMarket-1": {"extends": "SpotMarket"},
    "SpotMarket-2": {"extends": "SpotMarket"},
    "IndexMarket-I": {
        "class": "IndexMarket",
        "tickSize": 0.00001,
        "marketPrice": 300.0,
        "outstandingShares": 25000,
        "markets": ["SpotMarket-1", "SpotMarket-2"],
    },
    "FCNAgent": {
        "class": "FCNAgent",
        "numAgents": 100,
        "markets": ["Market"],
        "assetVolume": 50,
        "cashAmount": 10000,
        "fundamentalWeight": {"expon": [1.0]},
        "chartWeight": {"expon": [0.0]},
        "noiseWeight": {"expon": [1.0]},
        "noiseScale": 0.001,
        "timeWindowSize": [100, 200],
        "orderMargin": [0.0, 0.1],
    },
    "FCNAgents-1": {"extends": "FCNAgent", "markets": ["SpotMarket-1"]},
    "FCNAgents-2": {"extends": "FCNAgent", "markets": ["SpotMarket-2"]},
    "FCNAgents-I": {"extends": "FCNAgent", "markets": ["IndexMarket-I"]},
    "ArbitrageAgents": {
        "class": "ArbitrageAgent",
        "numAgents": 100,
        "markets": ["IndexMarket-I", "SpotMarket-1", "SpotMarket-2"],
        "assetVolume": 50,
        "cashAmount": 150000,
        "orderVolume": 1,
        "orderThresholdPrice": 1.0,
    },
}

  • SpotMarket-1 と SpotMarket-2 が2つの株式です。どちらも extends により SpotMarket ブロックの設定を引き継ぎます（extends による継承 を参照）。市場価格は300から始まり、ファンダメンタル価格はひとりでに動くことはありません。

  • IndexMarket-I は、2つの株式から構成される IndexMarket です。2つの株式の outstandingShares が同じなので、そのファンダメンタル価格は2つの株式のファンダメンタル価格の平均です（IndexMarket を参照）。インデックスは独自の板を持つため、その市場価格は、2つの株式の市場価格の平均である インデックス値 と乖離することがあります。

  • FCNAgents-1、FCNAgents-2、FCNAgents-I はそれぞれ100体のFCNエージェントで、各グループは自分の市場でだけ取引します。これらは FCNAgent ブロックの設定を共有しており、その設定は ファンダメンタリスト、チャーティスト、ノイズトレーダー の設定から meanReversionTime を除いたものです。

  • ArbitrageAgents は、3つの市場すべてで取引する100体の ArbitrageAgent エージェントです。

  • 最初のセッション（100ステップ）は板を埋めるだけで、maxHighFrequencyOrders: 0 により裁定エージェントは動作しません。2番目のセッション（500ステップ）では注文が約定します。各ステップで最大3体のFCNエージェントが注文を出し、そのそれぞれの後に最大5体の裁定エージェントが動作できます（セッション を参照）。

  • 2番目のセッションには FundamentalPriceShock イベントが記載されています（イベント を参照）。triggerTime はセッションの開始時点から数えるので、0はステップ100を意味します。このステップで、spot 1のファンダメンタル価格が1 − 0.1倍され、300から270になります。

ショックが伝わるしくみ¶

裁定エージェントは、インデックス市場の市場価格とインデックス値を比べます。インデックス市場の市場価格がインデックス値を下回り、その差が orderThresholdPrice （1.0）を超えると、インデックスを2株買い、各株式を1株ずつ売ります。インデックス値を上回り、その差が1.0を超えると、その反対の売買を行います。注文は現在の市場価格での指値注文で、有効期間は1ステップなので、ほとんどの注文は約定しません。

spot 2のFCNエージェントはspot 2だけを見ており、そのファンダメンタル価格は300のままです。spot 2を300から動かせるのは裁定エージェントだけです。ショックの後、spot 1は270へ、インデックスは270と300の平均である285へ向かいます。すべての市場がファンダメンタル価格に達すれば、インデックス値も285になり、取引する理由はなくなります。ショックがspot 2に届きうるのは、市場が動いている間です：

  • spot 1がインデックスより速く下がると、インデックス市場の市場価格はインデックス値より高くなります。裁定エージェントはインデックスを売って2つの株式を買うため、spot 2は押し上げられます。

  • インデックスがspot 1より速く下がると、インデックス市場の市場価格はインデックス値より低くなります。裁定エージェントはインデックスを買って2つの株式を売るため、spot 2は押し下げられます。

実行¶

run_simulation は設定を1つのシードで実行します。spot 1とインデックスのFCNエージェントの fundamentalWeight の平均と、2番目のセッションのステップ数を変えることができます：

def run_simulation(
    seed: int,
    spot_weight: float = 1.0,
    index_weight: float = 1.0,
    main_steps: int = 500,
) -> SequentialRunner:
    """Run the simulation with the given fundamental weights.

    Args:
        seed (int): seed of the random number generator.
        spot_weight (float): mean fundamental weight of the FCN agents of spot 1.
        index_weight (float): mean fundamental weight of the FCN agents of the index.
        main_steps (int): number of steps of the main session.

    Returns:
        SequentialRunner: the runner after the run.

    """
    config: Dict[str, Any] = copy.deepcopy(CONFIG)
    config["FCNAgents-1"]["fundamentalWeight"] = {"expon": [spot_weight]}
    config["FCNAgents-I"]["fundamentalWeight"] = {"expon": [index_weight]}
    config["simulation"]["sessions"][1]["iterationSteps"] = main_steps
    runner = SequentialRunner(settings=config, prng=random.Random(seed))
    # hide the two time lines that main() prints
    with contextlib.redirect_stdout(io.StringIO()):
        runner.main()
    return runner

python tutorial_shock_transfer.py は、まずサンプルをシード42で実行します。いくつかのステップについて、3つの市場の市場価格と、spot 1とインデックスのファンダメンタル価格を出力します：

step  spot 1  spot 2   index  fund 1  fund I
  99  300.00  300.00  300.00  300.00  300.00
 100  298.63  302.96  297.75  270.00  300.00
 101  298.27  302.96  298.75  270.00  285.00
 150  280.96  303.34  293.49  270.00  285.00
 200  275.87  297.86  287.77  270.00  285.00
 300  276.99  292.36  282.22  270.00  285.00
 599  270.84  297.32  285.30  270.00  285.00

  • ステップ99までは注文が約定しないため、すべての価格は300です。

  • ステップ100で、spot 1のファンダメンタル価格が270に下がります。インデックスのファンダメンタル価格は1ステップ遅れて変わります。インデックスはあるステップのファンダメンタル価格をその前のステップの終わりに計算しますが、その時点ではまだショックが起きていないためです。

  • その後、spot 1とインデックスは新しいファンダメンタル価格に向かって動きます。

また、shock_transfer_prices.png も保存します：

spot 2のファンダメンタル価格は300のままですが、spot 2はステップ300から499の間に平均で約291となり、ステップ480には285.24まで下がります。この実行では、spot 1はステップ379まで新しいファンダメンタル価格である270より上にとどまる一方、インデックスはステップ228に285を下回り、ステップ418には275.94まで下がります。そのためインデックス市場の市場価格は平均してインデックス値より低くなり、裁定エージェントがインデックスを買って株式を売ることが、その反対よりも多くなります。合計で、spot 2を26株売り、インデックスを18株買います。これがショック伝搬です。また、裁定エージェントはspot 1も18株多く持って実行を終えます。spot 1の売り注文は合計3260株で、買い注文は2715株だけですが、約定するのは買い注文の方が多いためです（買いは597株、売りは579株）。

どちらの市場が先に反応するか¶

Plhamのチュートリアルの2つのユースケースは、spot 1とインデックスがショックにどれだけ速く反応するかを変えます。スクリプトは3つのケースを比べます：

# the mean fundamental weight of the FCN agents of spot 1 and of the index
CASES: Dict[str, Tuple[float, float]] = {
    "same speed": (1.0, 1.0),
    "spot reacts faster": (1.0, 0.1),
    "index reacts faster": (0.1, 1.0),
}

ノイズ成分の重みは1.0のままなので、ファンダメンタル成分の重みが0.1のエージェントはほとんどノイズトレーダーであり、その市場は新しいファンダメンタル価格へゆっくりとしか動きません。compare は各ケースをシード42から51の10個のシードで実行し、measure をそれらで平均します。実行を短くするため、2番目のセッションは100ステップだけです：

def measure(runner: SequentialRunner) -> Dict[str, float]:
    """Measure the reaction of spot 2 and of the arbitrage agents in the main session.

    Args:
        runner (SequentialRunner): the runner after the run.

    Returns:
        Dict[str, float]: the mean gap between the index market price and the
        index value (``premium``), the mean market price of spot 2 minus its
        fundamental price 300 (``spot 2``), and the net number of shares of spot 2
        and of the index bought by all the arbitrage agents (``arb spot 2`` and
        ``arb index``).

    """
    simulator = runner.simulator
    spot1 = simulator.name2market["SpotMarket-1"]
    spot2 = simulator.name2market["SpotMarket-2"]
    index = simulator.name2market["IndexMarket-I"]
    main_session = simulator.sessions[1]
    start = main_session.session_start_time
    times = range(start, start + main_session.iteration_steps)
    spot1_prices = spot1.get_market_prices(times=times)
    spot2_prices = spot2.get_market_prices(times=times)
    index_prices = index.get_market_prices(times=times)
    arbitrage_agents = simulator.agents_group_name2agent["ArbitrageAgents"]
    initial: int = 50 * len(arbitrage_agents)
    return {
        "premium": statistics.mean(
            price - (a + b) / 2
            for price, a, b in zip(index_prices, spot1_prices, spot2_prices)
        ),
        "spot 2": statistics.mean(spot2_prices) - 300.0,
        "arb spot 2": sum(
            agent.get_asset_volume(market_id=spot2.market_id)
            for agent in arbitrage_agents
        )
        - initial,
        "arb index": sum(
            agent.get_asset_volume(market_id=index.market_id)
            for agent in arbitrage_agents
        )
        - initial,
    }

価格の後に、スクリプトはケースごとに1行を出力します：

case                premium spot 2    up arb spot 2 arb index
same speed            -0.16  -0.18  4/10        0.0       5.9
spot reacts faster     0.53   0.35  7/10        2.3      -0.1
index reacts faster   -0.46  -0.51  4/10       -4.1      11.9

  • premium はインデックス市場の市場価格からインデックス値を引いたもの、spot 2 はspot 2の市場価格から300を引いたものです。どちらも2番目のセッションでの平均です。

  • up は、spot 2が平均で300を上回ったシードの数です。

  • arb spot 2 と arb index は、裁定エージェントが合計で買ったspot 2とインデックスの株数です。負の数は売ったことを表します。

spot 1が速く反応する場合、プレミアムは正になります。裁定エージェントはspot 2を買い、10個のシードのうち7個でspot 2は300を上回ります。インデックスが速く反応する場合、プレミアムは負になります。裁定エージェントはインデックスを買ってspot 2を売り、spot 2は他のケースより低くなります。これはPlhamのチュートリアルと同じ方向です。Plhamでは、spot 2は1つ目のケースで上がり、2つ目のケースで下がります。

効果は小さいです。表では、spot 2の動きは平均で1価格単位未満ですが、シード42の実行では、spot 2はステップ300から499の間に300より約9低くなります（プロットを参照）。他のシードでは細部が変わります。シード52から61では、spot 1が速く反応する場合、spot 2は平均で300より0.08低く、300を上回るのは10個のシードのうち4個だけですが、それでもインデックスが速く反応する場合より高くなります。これらのシードでは、spot 2 の列で same speed と index reacts faster の順位も入れ替わります。変わらないのは、spot 1またはインデックスが速く反応する場合のプレミアムと arb spot 2 の符号で、これらの方が仕組みをより明確に示します。2番目のセッションをすべて使う compare(SEEDS, main_steps=500) でも3つのケースの順位は同じですが、実行には数倍の時間がかかります。裁定エージェントの注文はすべてが約定するわけではないため、arb index は arb spot 2 のちょうど−2倍にはなりません。

Plhamとの違い¶

  • PAMSでは、裁定エージェントの markets に、インデックスだけでなく構成市場も記載する必要があります（エージェント のArbitrageAgentを参照）。サンプルはそのように設定されています。

  • PAMSとPlhamは異なる乱数生成器を使うため、同じ設定とシードでも価格は異なります。

  • Plhamのチュートリアルでは、各ケースを10回以上試行するよう求めています。このチュートリアルでは、2番目のセッションを短くして10個のシードで実行し、平均を出力します。
