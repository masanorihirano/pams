TensorFlowAgentParallelRunner¶

class pams.runners.TensorFlowAgentParallelRunner(settings, prng=None, logger=None, simulator_class=<class 'pams.simulator.Simulator'>)[ソース]¶

TensorFlow のエージェント並列ランナークラス。これは実験的な機能です。

このランナーは、pams.agents.Agent.submit_orders() で TensorFlow を使うエージェント（例えば Keras のモデル）向けにワーカープロセスを準備した pams.runners.MultiProcessAgentParallelRunner です。エージェントが決定的であり、TensorFlow が同じスレッド数を使う限り（後述）、シミュレーション結果は、同じ設定と同じシードの pams.runners.SequentialRunner の結果と同一になります。

TensorFlow は PAMS のオプションの依存パッケージです。import pams は TensorFlow をインポートせず、このランナーが作成されたときにインポートされます。TensorFlow がインストールされていない場合は ImportError が送出されます。pip install tensorflow でインストールしてください（CPU 専用版であれば pip install tensorflow-cpu）。

TensorFlow は fork セーフでないため、ワーカープロセスはデフォルトで spawn によって起動されます。つまり、default_start_method は "spawn" です。TensorFlow が一度でも演算を実行すると、そのプロセスはスレッドプール（GPU の場合は CUDA コンテキストも）を持ちますが、fork で起動されたプロセスは fork を呼び出したスレッドのコピーしか持ちません。fork されたプロセスでは、TensorFlow のスレッドプールを使う演算（例えば大きな行列積）がハングし、GPU は使えず、TensorFlow を設定することもできなくなります。このような fork は、例えばエージェントがメインプロセスでモデルを構築した場合や、同じプロセスで先に pams.runners.SequentialRunner を実行した場合に簡単に起こります。spawn で起動されたプロセスは新しいインタープリターを開始し、TensorFlow を自身で初期化します。それでも、設定ファイルの simulation.startMethod が優先されます。TensorFlow がメインモジュールのトップレベルで使われていなければ forkserver も安全であり、fork はシミュレーションの前にメインプロセスで TensorFlow が使われていない場合にのみ動作します。

各ワーカープロセスは、タスクを実行する前に一度だけ、設定ファイルの simulation の以下のキーで TensorFlow を設定します：

  • tensorflowIntraOpThreads （int ≥ 1）：各ワーカープロセスで、TensorFlow が 1 つの演算（例えば行列積）の実行に使うスレッド数です。デフォルトは、CPU 数を同時にタスクを実行するワーカープロセス数、すなわち numParallel とセッションの maxNormalOrders の最大値の小さい方（最小 1）で割った値です。これは、ワーカープロセス全体で CPU 数より多くのスレッドを使わないようにするためです。TensorFlow はデフォルトでは各プロセスですべての CPU を使います。TensorFlow の結果はこの値によって変わることがあります（後述）。

  • tensorflowInterOpThreads （int ≥ 1）：各ワーカープロセスで、TensorFlow が互いに独立した演算を同時に実行するために使うスレッド数です。デフォルトは 1 です。

  • tensorflowGpuMemoryGrowth （bool）：各ワーカープロセスで、認識されているすべての GPU のメモリ増加（memory growth）を有効にするかどうかです。デフォルトは true です。メモリ増加が無効だと、TensorFlow は GPU のメモリのほぼすべてを最初にその GPU を使うプロセスに割り当てるため、GPU を共有する他のワーカープロセスはメモリ不足のエラーで失敗します。TensorFlow のデフォルトの動作を維持するには（例えば各ワーカープロセスが専用の GPU を使う場合）、false に設定してください。

その後、pams.runners.MultiProcessAgentParallelRunner と同様に、_get_worker_initializer で与えられる初期化関数が呼び出されます（例えば、読み取り専用のモデルをワーカープロセスごとに一度だけ読み込むため）。これらのキーはメインプロセスの TensorFlow を設定しません。tensorflowGpuMemoryGrowth が true の場合、初期化関数が呼び出される前に TensorFlow が GPU を列挙するため、初期化関数は環境変数 CUDA_VISIBLE_DEVICES でワーカープロセスの GPU を選択できません。代わりに tf.config.set_visible_devices を使ってください。

注釈

pams.runners.MultiProcessAgentParallelRunner と同様に、このランナーはタスクごとにエージェントと市場、すなわちシミュレーション全体を pickle 化します。エージェントが保持する tf.Tensor と tf.Variable はその値のコピーとして pickle 化され、Keras 3 のモデルは .keras 形式で保存することで pickle 化されます。これには小さなモデルでも数十ミリ秒かかり、すべてのタスクで、他のエージェントのタスクでも行われます。tf.function で作られたオブジェクトは、モジュールのトップレベルで定義されていても pickle 化できません。そのため、エージェントはモデルを属性として保持するべきではありません。代わりに、エージェントはモデルのキー（例えば保存されたモデルのパス）を保持し、モジュールのトップレベルにあるキャッシュ（例えば、モデルを読み込む関数を functools.lru_cache() でデコレートしたもの）からモデルを取得するべきです。そうすれば、各ワーカープロセスは最初のタスクまたはワーカーの初期化関数でモデルを一度だけ読み込んで以降のタスクで再利用し、pams.runners.SequentialRunner も同じエージェントを実行できます。

注釈

ワーカープロセスから返されるのは、注文とエージェントの疑似乱数生成器（prng）の状態のみです。TensorFlow の乱数状態（例えばグローバルシードや tf.random.Generator）は返されず、どのワーカープロセスがエージェントを実行するかは実行ごとに変わります。pams.runners.SequentialRunner と同じ結果を得るには、エージェントは prng から乱数（例えば tf.random.stateless_normal などのステートレスな乱数演算のシード）を生成するべきです。

モデルは、どのプロセスでも同じ出力を返す必要もあります。CPU では、TensorFlow がスレッド間で分割する演算（例えば長い軸に沿ったリダクションや行列積）の出力は、tf.config.experimental.enable_op_determinism を使っても、intra-op スレッド数によって変わります。このランナーのデフォルトのスレッド数は CPU 数、numParallel、maxNormalOrders によって決まり、TensorFlow がすべての CPU を使うメインプロセスのスレッド数とは異なることがあります。そのため、pams.runners.SequentialRunner と同一の結果や、異なる numParallel の間で同一の結果を得るには、tensorflowIntraOpThreads を明示的に設定し、pams.runners.SequentialRunner を実行するプロセスでも、TensorFlow が初期化される前に tf.config.threading.set_intra_op_parallelism_threads で同じ数を設定してください。GPU では、メインプロセスとワーカープロセスで tf.config.experimental.enable_op_determinism を呼び出さない限り、一部の演算は決定的になりません。

警告

このランナーがシミュレーションを速くするのは、pams.agents.Agent.submit_orders() 内の TensorFlow の計算が、タスクごとにシミュレーションを pickle 化するコストよりもはるかに重い場合に限られます。さらに、各ワーカープロセスは起動時に TensorFlow をインポートして初期化するため、プロセスごとに数秒の時間と数百メガバイトのメモリを要します。

default_start_method: Optional[str] = 'spawn'¶

設定ファイルで simulation.startMethod が設定されていない場合に使われる、ワーカープロセスの開始方式。TensorFlow は fork セーフでないため、"spawn" です。

型:

Optional[str]
